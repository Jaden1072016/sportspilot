# Alert and iPhone push design

## Current state
- In-app status display and manual browser **test notification** are implemented.
- LIVE research opportunity notifications, app-closed scanning, persistent push and web-push delivery **are NOT yet implemented**.
- `app/netlify/functions/push-register.mjs` deliberately returns HTTP 501: do not pretend a subscription was created.

## While app visible (safe initial milestone)
1. Poll score/game state and market data using source-appropriate rates (starter default 30s). Avoid rerendering every interaction when nothing changed.
2. Re-evaluate *independent* projections from freshly fetched data, then verified contract mapping and executable price separately.
3. Compare selected 3×–5× gross payout constraint, net EV and safety blockers. Record state/quote/model hashes.
4. Suppress duplicates: per market+side+state signature and cooldown. Re-alert only for materially changed edge or price; configurable max alerts/hour.
5. Show why: player lineup, rotation, matchup, source data age, timestamp, predicted probability with calibrated uncertainty, ask price, depth, fee assumption and model version.
6. Notify only after explicit user permission; sound/quiet hours and pause must work. Even if 'qualified', prevent direct order placement.

## App closed / iPhone Home Screen PWA
A browser tab cannot reliably keep a JavaScript loop alive when the iPhone is locked or when Safari discards it. A server-side scan must run independently. The iOS Safari Add to Home Screen web app supports web push in eligible supported iOS versions only with user permission and properly deployed HTTPS, manifest, service worker and Push API handling.

Reliable architecture:
```
Provider feeds → permitted central scanner → model+evaluation → dedupe/TTL queue
    → secure subscription database → VAPID-authenticated Web Push → iPhone PWA
```

### Required components BEFORE promising push
- VAPID key pair generated by user in trusted server environment. **Do not include private key in ZIP, front-end JS, public repo or a chat screenshot.** Keep the private key as a secured hosting secret.
- Client `PushManager.subscribe` triggered by user action, browser notification permission, service worker `push` and `notificationclick` handlers, `showNotification` with non-sensitive generic body and quick expiry.
- Server authenticated endpoint to register/unregister a subscription, verify origin/CSRF and avoid public subscription harvesting. Persistent encrypted storage and removal on user request.
- Scheduled scanning service with durable state. Netlify scheduled functions exist, but their exact cadence, 30-second execution limit and free-credit limits must be verified for a live 15–30 second goal. Do not claim a free background function runs continuously 24/7.
- Only send push when a new opportunity survives all gates and the quote remains fresh at decision time. Push is a prompt to verify again, NOT a guaranteed executable opportunity.
- Respect 410 Gone invalid subscriptions, endpoint timeouts, retry rate limits, backoff, deduplication, timezone/quiet hours and notification click navigation to correct market details.
- End-to-end test on actual iPhone, locked screen, PWA installed, permission granted. Measure time from sports source update to alert delivery; ensure alerts that arrive late are marked expired.

### No-fee operating options, with caveats
A spare always-on personal PC can run the backend on the user's own connection, but reliable external HTTPS push, static address/reverse proxy, power uptime, and security must be engineered. Zero-subscription serverless hosting may pause, cap execution or meter invocations. First perform a documented limits check; offer a lower cadence or on-open-only notifications if continuous scanning cannot be guaranteed without paid infrastructure.

## Alert schema
`id, game_id, contract_slug, side, exact_line, model_version, model_snapshot_ts, quote_source_ts, quote_fetch_ts, expires_at, p_model, p_uncertainty, gross_multiple, net_ev, fee_assumption_version, slippage_estimate, depth_size, eligibility, evidence[], warnings[], blockers[], dedupe_key, sent_at, opened_at`

## Alert policy
- One position is never called 'risk-free', 'guaranteed', or 'easy money'.
- If model isn't calibrated or performance evidence not adequate, only show a **research candidate** without a trade recommendation. Current app does not send research candidate alerts.
- User can mute per league, team, player, event and time window.
- If quote or game-state freshness check fails, suppress alert; if previously sent, mark expired upon opening.
